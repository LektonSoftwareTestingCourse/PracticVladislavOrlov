# Чек-листы — Authorization и Card Management

Базовый URL: Authorization `:8083`, Card Management `:8081`. Шаги и ожидаемые результаты — в [test-design.md](test-design.md) по ID кейса, приоритеты и критерии выхода — в [тест-плане](test-plan.md#6-критерии-выхода). Пункт отмечается, только если пройдены все перечисленные в нём кейсы.

## 1. Дымовое тестирование (smoke)

Выполняется при каждой сборке стенда, ~5 минут. Любой красный пункт — стоп.

- [ ] S1. `docker compose ps` → все контейнеры `Up (healthy)`
- [ ] S2. `GET :8083/health` → 200, `status=ok`, `service=authorization`, `dependencies.cardManagement=ok` (AUTH-1-01)
- [ ] S3. `GET :8081/health` → 200, есть поле `cardsInDatabase` (CMS-1)
- [ ] S4. `POST :8081/api/cards/generate` с `count=20` → 200, создано 20 карт (CMS-7)
- [ ] S5. `GET :8081/api/cards?limit=5` → 200, 5 карт, есть `total` (CMS-4)
- [ ] S6. `GET :8081/api/cards/{pan}` по карте из S4 → 200 (CMS-3-01)
- [ ] S7. Авторизация по ACTIVE-карте на 100 копеек → APPROVED `00`, есть RRN и authCode (AUTH-12-01)
- [ ] S8. Авторизация по несуществующему PAN → DECLINED `14` (AUTH-3-02)
- [ ] S9. `./scripts/smoke-test.sh` → `ALL CHECKS PASSED`

## 2. Критический путь (P1)

**Жизненный цикл карты**

- [ ] Создание карты: Луна, `ACTIVE`, expiry +3 года; без `bin`/имени → 400 — CMS-2-01, CMS-2-02
- [ ] Чтение: существующая → 200, несуществующая → 404 — CMS-3-01, CMS-3-02
- [ ] `PATCH` меняет только переданные поля; `status=XYZ` → 400 — CMS-5-01…05
- [ ] `DELETE` → `DELETED`, затем `GET` → 404, авторизация → `14` — CMS-6-01…03
- [ ] `reserve` уменьшает баланс; сумма > баланса → отказ, баланс не изменился — CMS-9-01, CMS-9-02

**Решение об авторизации**

- [ ] PAN не найден → `14` — AUTH-3-01, AUTH-3-02
- [ ] `INACTIVE` → `CARD_INACTIVE` — AUTH-4-01, AUTH-4-02
- [ ] `BLOCKED` → `CARD_BLOCKED` — AUTH-5-01, AUTH-5-02
- [ ] `EXPIRED` → `54` — AUTH-6-01, AUTH-6-02
- [ ] Срок в прошлом → `54`; текущий и следующий месяц → проход — AUTH-7-01…03
- [ ] Дневной лимит → `61`; граница включительна — AUTH-8-01, AUTH-8-02, NP-1…3
- [ ] Месячный лимит → `61`; граница включительна — AUTH-9-01, AUTH-9-02, NB-1…3
- [ ] Баланс → `51`; граница включительна — AUTH-10-01, AUTH-10-02, BAL-1…3
- [ ] Успех → `00`, баланс уменьшен на сумму, `limit_usage` обновлён; отказ ничего не меняет — AUTH-12-01, AUTH-12-02
- [ ] Порядок проверок: при двух нарушениях — код более раннего — AUTH-12-04, AUTH-12-05

**Отказоустойчивость и идентификаторы**

- [ ] CMS недоступна → `05` / `ISSUER_TIMEOUT` (не `14`); отказ на `reserve` не списывает средства — AUTH-11-01…03
- [ ] RRN — 12 цифр, уникален при 50 параллельных авторизациях — AUTH-13-01, AUTH-13-02
- [ ] Health Authorization и Card Management — AUTH-1-01, CMS-1-01

## 3. Расширенный чек-лист (P2)

- [ ] Health при остановленной CMS и пустой БД — AUTH-1-02, CMS-1-02
- [ ] Bin-lookup: 200 → обогащение; 5xx → 2 retry и fallback; недоступен → fallback — AUTH-2-01…03
- [ ] Отрицательная сумма не одобряется и не увеличивает баланс — AUTH-12-03
- [ ] Месячный расход = сумма дней текущего месяца, прошлый месяц не учитывается — AUTH-15-01, AUTH-15-02
- [ ] Reversal возвращает баланс и уменьшает `limit_usage` на сумму транзакции; неизвестный rrn → «не найдено» — AUTH-B1-01…03
- [ ] Пагинация и фильтры `status`, `bin`; удалённые карты не в списке — PAG-1…5, CMS-4-01…03
- [ ] Генератор: по 20 карт на BIN, диапазоны, доли статусов в интервале — CMS-7-01…03
- [ ] Луна: сгенерированные PAN валидны, PAN с неверной контрольной цифрой не возвращает 200 — CMS-8-01, CMS-8-02
- [ ] Попарный набор авторизации прогнан целиком — PW-AUTH-01…37
- [ ] Попарный набор создания карты прогнан целиком — PW-CMS-01…20

## 4. Бонусные проверки (P3)

- [ ] authCode — 6 символов `A-Z0-9`, без дублей на 1000 авторизаций — AUTH-14-01, AUTH-14-02
- [ ] Outbox: `card.created/updated/deleted` → `PROCESSED`; RabbitMQ недоступен → 3 попытки, затем `FAILED` — CMS-B1-01…04
- [ ] Граничный кейс с исчерпанным лимитом и нулевой суммой — NP-4 (результат фиксируется, вопрос Q3)
